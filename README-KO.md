# 번역 프리셋·단어장

Marinara Engine 2.4.x의 기본 양방향 번역에 다음 기능만 추가하는 확장입니다.

- 번역용 AI 프롬프트 프리셋을 여러 개 만들어 공용으로 관리
- Outgoing Message Prompt와 Incoming Response Prompt에 각각 프리셋 적용
- 채팅마다 양방향 단어장 저장
- 장르·시대·지역·배경 등을 지정하는 선택형 기타 지침
- My Language를 한국어로 자동 설정
- 번역 Provider를 AI로 고정하고 선택한 Connection을 새 채팅의 공용 기본값으로 사용
- 이전 대화에서 확립된 말투·존비어·호칭·용어·문체를 번역 참고 Context로 사용

기존 2.3.x 확장의 문자 체계 감지, 번역 방향 전환, 언어 설정, 추가 번역 지침, 플로팅 버튼은 포함하지 않습니다. 번역 방향과 대상 언어는 Marinara Engine 2.4.x의 기본 기능이 처리합니다.

## 사용법

1. Marinara Engine에서 외부 확장 기능의 두 안전 게이트를 활성화합니다.
2. **Settings → Addons → External Extensions**에서 ZIP을 가져옵니다.
3. 확장의 코드를 검토한 뒤 **Full page access**를 승인하고 활성화합니다.
4. 채팅 설정의 **번역** 섹션을 열고 **번역 프리셋·단어장**에서 설정합니다.
5. Provider는 확장이 **AI (연결 경유)**로 고정합니다. Connection은 처음 한 번 선택하면 이후 새로 만드는 채팅에 기본으로 적용됩니다.

각 방향의 기본 선택은 **채팅 설정 유지**입니다. 다른 프리셋을 선택하면 Marinara의 실제 Outgoing Message Prompt 또는 Incoming Response Prompt 입력란에 프롬프트 전문이 즉시 표시됩니다. 확장 하단의 **저장**을 누르면 선택 상태와 프롬프트가 함께 저장됩니다. 다시 **채팅 설정 유지**를 선택하면 프리셋 적용 전 프롬프트로 돌아갑니다.

프리셋 이름과 프롬프트 전문 입력란은 **새 프리셋**을 누르거나 **관리할 프리셋**에서 사용자 프리셋을 선택하면 표시됩니다. 사용자 프리셋은 수정·삭제할 수 있고 내장 프리셋은 읽기 전용입니다.

1.3.6부터 사용자 프리셋 삭제는 확인 직후 공용 저장소에 반영됩니다. 별도로 **저장**을 누르지 않아도 채팅 전환·새로고침 후 삭제 상태가 유지됩니다. 삭제 저장에 실패하면 목록을 유지하고 오류를 표시하며, 다른 미저장 설정은 함께 저장하지 않습니다.

확장이 활성화된 상태에서 채팅 설정의 **번역** 섹션을 열면 Provider가 AI로 고정되고 **My Language**가 `Korean`으로 자동 설정됩니다. Connection에서 비어 있지 않은 값을 선택하면 확장 공용 기본값으로 저장되며, 이후 새로 만드는 채팅에 적용됩니다. 이미 생성된 채팅은 각 채팅에 저장된 Connection을 그대로 사용합니다. 다른 Connection을 선택하면 앞으로 생성할 채팅의 공용 기본값만 갱신됩니다.

**대사 지침 추가**를 켜면 Incoming Response Prompt 끝에 `# Character Voice Instructions` 제목과 실제 지침 내용이 추가됩니다. 끄고 저장하면 확장이 추가했던 지침을 제거합니다. Outgoing Message Prompt에는 적용되지 않으며 설정과 내용은 채팅별로 저장됩니다.

단어장은 번역 요청을 보낼 때 `# Glossary` 제목 아래에 내부적으로 추가됩니다.

**기타 지침 추가**를 켜면 장르·시대·지역·배경·분위기·세계관 등을 자유롭게 입력할 수 있습니다. 체크되어 있고 값이 있을 때만 번역 요청에 별도 참고 정보로 추가되며, 모델은 이에 적합한 어휘와 용어를 선택하는 데만 사용합니다. 이 정보를 근거로 원문에 없는 내용이나 설정을 번역문에 추가하지 않도록 제한합니다. 체크하지 않거나 비워 두면 기존 번역 동작에 영향을 주지 않습니다.

**이전 대화를 번역 Context로 포함**은 기본적으로 꺼져 있습니다. 꺼져 있으면 과거 메시지를 읽거나 번역 본문에 추가하지 않으므로 기존 번역 동작과 동일합니다. 켜면 기본적으로 Incoming Response 번역에만 Context를 추가합니다. **유저 입력 번역에도 포함**을 켠 경우에만 Outgoing Message 번역에도 추가합니다. 원문과 번역문은 각각 독립적으로 포함할 수 있으며, 최근 메시지 수는 기본 3개이고 1~10개 사이에서 설정할 수 있습니다.

Context는 현재 번역 대상보다 앞에 메시지 단위로 배치되며 user와 assistant 메시지를 모두 포함합니다. 원문과 번역문을 함께 선택하면 같은 메시지 안에 한 쌍으로 전달됩니다. 저장된 번역문이 없는 메시지는 선택 가능한 정보만 포함하고 건너뛰어도 오류가 발생하지 않습니다. 모델에는 Context가 인물 관계, 말투, 존비어, 한국어 호칭, 고유명사 및 문체 일관성만을 위한 참고 자료이며 다시 번역하거나 출력해서는 안 된다는 지침이 함께 전달됩니다.

프리셋, 단어장과 Context는 AI 번역 요청에만 적용됩니다. Google, DeepL, DeepLX는 사용자 정의 시스템 프롬프트를 받지 않으므로 변경하지 않습니다.

## 기본 프리셋

1.3.8은 프롬프트 문구와 동작을 변경하지 않고 작업 종류별 파일로 분리한 버전입니다.

1.3.5부터 기본 프리셋은 공통 → 영어 → 중국어 → 일본어 → 원문 대사 병기 순으로 표시합니다. 각 언어 안에서는 기존판 → v2 → 의역 → 번역투 순이며, 사용자 프리셋은 기본 프리셋 뒤에 기존 순서대로 표시합니다. 프리셋 내용과 선택값은 변경하지 않습니다.

1.3.4에서는 중국어→한국어 문학·RP v2 전문을 교체하고 아래 3종을 기본 목록에 추가했습니다. 새 3종은 v2 업데이트 여부와 관계없이 표시되며 기존 사용자 프리셋은 보존합니다. 이미 채팅에 적용한 프롬프트를 바꾸려면 해당 프리셋을 다시 선택하고 저장하세요.

- **영어→한국어 의역·문학·RP**: 원문의 의미·감정·효과를 중심으로 자연스럽게 재구성
- **영어→영문학 번역체·RP**: 자연스러운 한국어 범위에서 원문의 문체·구조·리듬·이미지를 보존
- **중국어→한국어 의역·문학·RP**: 중국어의 구조·품사 대응보다 의미와 문학적 효과를 중심으로 재구성

1.3.0의 초기 기본 목록은 기존 버전입니다. **프리셋 업데이트**를 누르면 “기존 버전을 유지하시겠습니까?”라는 선택이 표시됩니다.

- **예**: 영어·중국어·일본어·원문 대사 병기 v2를 기본 프리셋으로 추가하고 기존 4종도 유지합니다.
- **아니요**: 해당 기존 4종을 제거하고 v2로 교체합니다. 나머지 기본 프리셋은 유지합니다.
- **취소**: 변경하지 않습니다.

업데이트 선택은 확장 공용 저장소에 즉시 저장되며 업데이트 버튼은 사라집니다. 구버전을 유지했다면 **기존 버전 삭제** 버튼이 표시되고, 삭제 후에는 이 버튼도 사라집니다. 새로고침·채팅 전환·설정 저장 후에도 상태가 유지됩니다.

현재 저장된 사용자 v2 4종의 전문을 기본 프리셋으로 제공합니다. 원본 사용자 항목과 이름·내용이 정확히 같은 항목은 업데이트 시 통합하며, 별도로 수정된 사용자 항목은 보존합니다. 삭제된 구버전과 통합된 사용자 항목을 가리키는 채팅별 선택은 대응하는 v2로 연결합니다. 실제 Marinara 번역 프롬프트는 프리셋을 선택하고 **저장**하면 적용됩니다.

관리 버튼은 **새 프리셋 / 삭제 / 수정 취소 또는 생성 취소 / 프리셋 업데이트 또는 기존 버전 삭제** 순서로 한 줄에 표시되며 **저장**은 같은 줄 오른쪽에 배치됩니다. 사용자 프리셋이나 기존 기본 프리셋을 삭제할 때는 확인 경고가 표시됩니다.

- **채팅 설정 유지**: 기존 Outgoing 또는 Incoming 프롬프트를 변경하지 않음
- **자연스러운 RP**: 확장에 원래 포함되어 있던 자연스러운 역할극 번역
- **범용 문학·RP**: OOC·메타 지시와 사용자 명령까지 빠짐없이 포함하는 범용 문학·역할극 번역
- **영어→한국어 문학·RP**: 영어 특성에 맞춘 자연스러운 한국어 렌더링
- **중국어→한국어 문학·RP**: 중국어 어순, 양사, 把자문·被자문을 고려한 한국어 렌더링
- **일본어→한국어 문학·RP**: 일본어 대사와 서술 호흡을 고려한 한국어 렌더링
- **원문 대사 병기·한국어 RP**: 외국어 대사를 원문 그대로 유지하고 바로 뒤에 한국어 번역을 괄호로 병기

## 단어장 형식

한 줄에 한 쌍을 `사용자 언어 용어 = 모델 언어 용어` 형식으로 입력합니다.

```text
마리나라 = Marinara
로어북 = lorebook
누들 = Noodle
```

단어쌍은 좌우 순서와 관계없이 양방향으로 적용됩니다. 어느 쪽도 원문에 나타나지 않거나 양쪽이 함께 나타나면 AI가 대상 언어에 맞는 쪽을 선택하도록 양방향 쌍으로 전달합니다.

## 저장 범위

- 프리셋 목록과 프롬프트 본문은 확장 전체에서 공용입니다.
- 번역 Connection 기본값은 확장 전체에서 공용이며 새로 생성하는 채팅에만 적용됩니다.
- 적용한 프리셋 본문은 Marinara의 해당 채팅 Outgoing·Incoming 프롬프트에 저장됩니다.
- 단어장은 채팅별로 확장 저장소에 저장됩니다.
- 기타 지침의 사용 여부와 입력 내용은 채팅별로 확장 저장소에 저장됩니다.
- 이전 대화 Context의 사용 여부, Outgoing 적용 여부, 포함 항목, 메시지 수는 채팅별로 확장 저장소에 저장됩니다.
- 활성 채팅이 없을 때 저장한 값은 새 채팅의 기본값으로 사용됩니다.

## 프롬프트 파일 구조

`extension.js`에는 UI·저장·요청 처리와 프리셋 메타데이터를 유지하고, 프롬프트 전문은 `prompts/`에서 관리합니다.

- `general.js`: 범용 번역·자연스러운 RP·범용 문학·RP
- `literary.js`: 영어·중국어·일본어 문학·RP의 기존판과 v2
- `bilingual-dialogue.js`: 원문 대사 병기의 기존판과 v2
- `paraphrase.js`: 영어·중국어 의역
- `source-style.js`: 영어 영문학 번역체
- `reference.js`: 이전 대화·기타 지침·단어장·대사 지침의 참고 프롬프트

각 언어별 variant는 전체 문구를 그대로 포함합니다. 구버전 프롬프트는 기존 버전 유지 설정을 지원하기 위해 남겨 둡니다. `manifest.json`의 `jsPath` 배열 순서에 따라 파일을 결합하므로 별도 다운로드·동적 import·빌드 과정은 필요하지 않습니다. 배포 시 프롬프트 파일과 manifest를 함께 포함해야 합니다.

개발 검증은 `node tests/prompts-regression.mjs`로 실행합니다. 파일 순서·문법·프리셋 전문과 메타데이터의 SHA-256 기준값을 검사합니다. 분리 전 `extension.js` 경로를 인자로 전달하면 UI·설정 변환·Context·최종 번역 요청도 비교합니다. `tests/`는 배포 ZIP에 포함하지 않습니다.

## 권한 안내

이 확장은 `/api/translate` 요청의 AI 시스템 프롬프트를 수정해야 하므로 `full_page_access`를 요청합니다. 이전 대화 Context 옵션을 켠 경우에만 현재 채팅의 user/assistant 메시지를 Marinara의 로컬 API에서 읽어 기존 번역 요청에 포함합니다. 확장이 별도의 외부 서버로 데이터를 전송하거나 캐릭터·페르소나 라이브러리를 읽지는 않습니다.
